    How CloudGuard works

    CloudGuard checks infrastructure code for security mistakes before it gets deployed. A proven static analyzer finds the problems, and a language model explains them in terms of your file and writes a corrected version.

    What happens when you scan

    1. Checkov runs the policies

      Checkov is an open-source analyzer with over 1,000 policies for Terraform, CloudFormation, Kubernetes, Helm and Dockerfiles. It reports each resource that fails a policy, with the file and lines involved. The same file always gives the same findings.

    2. The findings get explained

      The file and Checkov's findings go to gpt-oss-120b, OpenAI's open-weight model running on Groq. For each finding it says what is actually at risk in your file and which setting to change. It also points out problems no policy covers, such as passwords in a Docker Compose file. Those are listed separately and don't affect the score.

    3. Earlier fixes are checked

      Findings are compared with findings from your own earlier scans using embeddings stored in PostgreSQL with pgvector. The closest matches and the patches written for them are used as examples, which keeps fixes consistent between files. Only your scans are searched.

    4. A patch is written

      The model rewrites the file with the findings addressed and marks changed lines with a # FIXED: comment. The page shows it as a diff against what you pasted.

    5. The scan is saved

      It goes into your history. A copy of the original and patched files is written to a private S3 bucket.

    Free explained scans

    Checkov results are always free. Explanations, extra review findings, patches and diagram checks use a paid model, so each visitor gets a few explained scans per day. After that, scans still run Checkov and show every finding, just without explanations or a patch.

    How the score works

    Only Checkov findings count, so the score is the same every time you scan the same file. CloudGuard rates each Checkov policy itself, because the open-source release doesn't include severities: public access and secrets are critical, missing encryption is high, logging and backups are medium, and tags and monitoring are low. Each finding adds points:

    SeverityPoints
    Critical30
    High12
    Medium4
    Low1

    The score is 100 × e−points / 80. The first serious problems cost the most, and a long list of minor warnings can't drag an otherwise sound file to zero. One critical finding gives 69, one high gives 86, and ten low ones give 88. Files Checkov doesn't support, such as Docker Compose, aren't scored.

    Diagram check

    Gemini 2.5 Flash reads the image and the Terraform together. It reports resources that appear in one but not the other, subnets placed differently, and connections the security groups or route tables don't allow. It doesn't try to read things like IAM permissions or port numbers from a picture. The Terraform also goes through a normal scan. A diagram check uses one of your free explained scans.

    Your data

    • There are no accounts. The first time you visit, your browser gets a random ID in a cookie, and every scan you run is filed under it. Nobody else can list, open or search your scans, and they're never used as examples for anyone else's patch.
    • Because history belongs to the cookie, it won't follow you to another device. Clearing your cookies loses access to it.
    • Clear history deletes your scans and findings from the database. The file copies in S3 aren't linked to your browser and aren't shown to anyone.
    • Checkov runs on this server. For explained scans, the file is also processed by Groq, and embeddings of the findings by Google. Don't paste real passwords or keys; swap them for placeholders first.
    • The free-scan counter stores a keyed hash of your IP address, not the address itself.

    Limits

    • Checkov only knows the policies it ships with. Passing every policy doesn't mean a file is secure.
    • Explanations and review findings come from a language model. They can be wrong or miss things, which is why they never change the score.
    • Read a patch before applying it and run terraform plan. A rewrite can change more than the lines it marks.
    • Files can be up to 120,000 characters. Diagrams can be up to 8 MB. Scans are rate limited per IP address.
