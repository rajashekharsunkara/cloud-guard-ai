What it looks for

  • Storage buckets and databases reachable from the internet
  • Data stored or sent without encryption
  • Security groups and IAM policies that allow too much
  • Passwords, tokens and keys written into the file
  • Missing logging, versioning and backups
  • Resources without ownership tags

A scan takes 10 to 30 seconds. Results are a review, not a guarantee. Read the limits before relying on them.

    How CloudGuard works

    CloudGuard reviews infrastructure code for security mistakes before it gets deployed. It reads Terraform and Docker Compose files, explains each problem it finds, and suggests a corrected file.

    What happens when you scan

    1. Review

      Your file is sent to OpenAI's open-weight gpt-oss-120b model, running on Groq, with instructions to look for the problems listed on the scan page. It returns a list of findings, each with a severity, the resource it affects and a suggested fix.

    2. Check earlier fixes

      Each finding is converted into an embedding with Google's Gemini embedding model and compared with findings from your own earlier scans, stored in PostgreSQL with pgvector. The closest matches and the patches written for them become examples for the next step, which keeps fixes consistent between files. Only your scans are searched.

    3. Write a patch

      The model rewrites the whole file with every finding addressed and marks changed lines with a # FIXED: comment. The page shows it as a diff against what you pasted.

    4. Score

      The score starts at 100 and drops for each finding. It never goes below 0.

    5. Save

      The scan goes into your history. A copy of the original and patched files is written to a private S3 bucket.

    Diagram check

    Gemini 2.5 Flash reads the image and the Terraform together. It reports resources that appear in one but not the other, subnets placed differently, and connections the security groups or route tables don't allow. It doesn't try to read things like IAM permissions or port numbers from a picture. The Terraform also goes through a normal scan.

    Your data

    • There are no accounts. The first time you visit, your browser gets a random ID in a cookie, and every scan you run is filed under it. Nobody else can list, open or search your scans, and they're never used as examples for anyone else's patch.
    • Because history belongs to the cookie, it won't follow you to another device. Clearing your cookies loses access to it.
    • Clear history deletes your scans and findings from the database. The file copies in S3 aren't linked to your browser and aren't shown to anyone.
    • What you paste is processed by Groq and Google. Don't paste real passwords or keys. Swap them for placeholders first.

    Limits

    • Findings come from a language model. It can miss problems, flag things that are fine or get the severity wrong. Use it alongside static checkers such as Checkov, tfsec or Trivy, not instead of them.
    • Read a patch before applying it and run terraform plan. A rewrite can change more than the lines it marks.
    • Files can be up to 120,000 characters. Diagrams can be up to 8 MB.

    API
